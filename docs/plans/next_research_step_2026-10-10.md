# Next research step: shared models, then test the assessments

10 October 2026. This is a proposal for discussion, not an executed experiment. Andrei is open to revising the previously frozen models and now considers removing LR regularization and grouping rare categories acceptable if the grouping is identical in both implementations. No cutoff or replacement model has been chosen or fitted. The original results remain the historical reference.

The full GBM already supplies a common candidate: the article full GBM and original full GBM produce identical holdout probabilities. Separate storage/fitting did not create a performance advantage. The three-predictor GBM is different because it is the article selection procedure's output. The current .027 AUC comparison is therefore a full-versus-reduced model trade-off, not a head-to-head demonstration that either whole assessment framework is better. Its practical importance remains undecided.

For LR, removing regularization alone does not repair the categorical design. There are redundant indicator columns and categories seen with only one outcome class. We should distinguish the two issues: redundancy makes individual coefficients nonunique; separation can prevent finite ordinary estimates. Our current code intentionally rejects a rank-deficient full design before optimization. Standard GLM software can sometimes fit an aliased design and mark terms undefined, so that guard is our strict specification choice, not proof that every likelihood comparison is mathematically impossible. However, simply bypassing the guard would not resolve separation or make coefficient-based fairness/explanation inference defensible. See [statsmodels pitfalls](https://www.statsmodels.org/stable/pitfalls.html), [R GLM documentation](https://www.stat.ethz.ch/R-manual/R-devel/library/stats/html/glm.html) and [nested GLM comparisons](https://www.stat.ethz.ch/R-manual/R-devel/library/stats/html/anova.glm.html).

A coherent revised model layer would use one common rare-category policy learned from fitting data, preserve -2/-1/0 as distinct special states, check full design rank and finite estimates, and fit one unpenalized LR artifact for both assessments. A six-plus-month band is still only an example. Grouping should reflect training support and repayment meaning, not a favorable AUC or significance outcome. The semantic mapping must match across frameworks; representation can still use reference coding for LR and full one-hot coding for GBM. If grouping is put in common data preparation for both model families, we must refit a shared GBM too. That new GBM need not retain the current AUC .7781, but both frameworks would evaluate the same new model. All affected assessment outputs would be recomputed in a new version; old results would not be overwritten.

The research improvement should be a better assessment decision, not a stronger model trained only for our framework. Fit each shared candidate once, then freeze the candidates. Both frameworks get the same records and predictions. A useful improvement could be a correct warning that an apparently adequate model fails under a declared operating condition, or a model recommendation with fewer observed decision errors. Scores looking different is not evidence of either benefit. The original article supplies profiles and a particular feature-selection rule, not a universal LR-versus-GBM ranking; any added cross-family ranking must be labeled our operationalization and fixed before evaluation.

My proposed first pilot is an information-quality failure: for a declared fraction of records, the latest repayment status is stale, represented by copying the previous month's recorded status into PAY_0. This changes reported information, not borrower behavior; it does not require interpreting -2 as delay or making up a monthly arrears update rule. The main question is whether full or intermediate models retain useful backup information that the smaller model discarded. Include clean data and several declared severities, common fault draws across candidates, and a separately declared alternative fault/affected-input check. No synthetic severity is an estimated real-world occurrence rate. No model gets retrained specifically to handle the test faults during the primary assessment comparison.

The pilot must calculate the article indicators as well as our additional quantities under those same conditions. We cannot assume SAFE misses the issue. A controlled comparison should include the published article selection outcome, an article-based assessment supplied with the same fault information, a simple rule using the chosen outcome loss, and the proposed fuller assessment. These distinguish useful extra test coverage from better decision logic. The later SAFE literature already discusses probability-sensitive metrics and aggregation; adding Brier or a composite score alone is not a demonstrated new contribution. See the locally reviewed [Correlation Metrics for Safe Artificial Intelligence](../context/sources/literature_2026-10-09/risks-13-00178.pdf) and [SAFE AI metrics: An integrated approach](../context/sources/literature_2026-10-09/1-s2.0-S266682702500204X-main.pdf).

For materiality, start by reporting missed-default flags and false-default flags per 1,000 records, together with probability loss and conditional uncertainty. Agree the acceptable clean-performance sacrifice and meaningful improvement before a final comparison. If a cost-weighted error criterion is adopted, its weights must reflect an externally stated preference or a declared sensitivity range; they are not bank profit or measured borrower harm. Taiwan outcomes do not identify counterfactual lending consequences. A worst-condition criterion is a deliberate protection objective, not expected annual risk without fault-frequency evidence. Plain always-full and always-small model choices should be retained as useful controls; if an assessment can abstain, report its coverage rather than rewarding rejection of every candidate.

Keep exploratory pilot results separate from confirmation. Method design may use development data; final assessment choices are frozen before evaluation on separate records and new fault realizations, with clean and adverse conditions reported. Fresh randomness alone cannot justify a hand-picked scenario; its relevance, severity range and transfer checks must be independently defensible. If only our method is given the relevant scenario, any advantage is from additional information. If both receive it and select the same candidate, there is no selection advantage. If a simple loss rule matches our fuller framework, credit the simpler mechanism. Selection itself can overfit evaluation criteria: [Cawley and Talbot (2010)](https://www.jmlr.org/papers/v11/cawley10a.html). Current Taiwan results remain exploratory because the dataset has been extensively inspected.

A secondary question, if needed for a separately declared study, is whether the article's significance-based reduction behaves differently from a rule based on an agreed acceptable loss when validation support varies. Nonsignificance does not establish a negligible loss, while a detectable difference need not be material. This is an existing statistical distinction, not an automatic novelty claim. It should not become an undisclosed search through experiments for a favorable result.

Recommended order: settle the shared LR/preprocessing version; fix the shared candidate pool; run one small declared information-quality pilot; determine whether it reveals a practical problem and whether SAFE already detects it; only then settle a fuller framework decision rule and confirmation protocol. Do not enlarge the methodology simply to create score differences. No model, source data, existing split or scientific stage output was changed while writing this note.
